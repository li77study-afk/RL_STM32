# 固定策略封装验证

日期：2026-11-16（Asia/Shanghai）。本次将固定红方决策从物理引擎移入独立的 `Game/fixed_policy.c/.h`，并分离训练基准与评估/演示挑战策略。

## 默认行为回归

重构前使用三张竞技场、固定出生/动作随机种子，记录 360 局中的 3,557 个步骤，得到动作与状态轨迹指纹 `8387578a`。重构后的训练基准得到同一步数和相同指纹。

原生测试同时检查：

- 输入状态和地图只读，同一输入的重复决策一致，返回值合法。
- 无效输入、结束回合和未知阶段回退到 WAIT。
- `Battle_Step()` 固定使用训练基准。
- `TankAgent_Evaluate()` 使用挑战阶段，显式阶段版本按传入阶段调用。
- 演示使用挑战阶段；非法动作由引擎回退到 WAIT。
- 原游戏规则、60000 回合学习对照和只读评估继续通过。

默认配置下三种种子的训练/挑战结果保持一致：

| 种子 | 训练基准胜/负/平 | 默认挑战胜/负/平 |
|---|---|---|
| 750 | 322 / 153 / 25 | 322 / 153 / 25 |
| 1 | 312 / 155 / 33 | 312 / 155 / 33 |
| 42 | 324 / 149 / 27 | 324 / 149 / 27 |

完整输出：[policy_refactor_test_results.txt](policy_refactor_test_results.txt)。

## 实际替换挑战函数的验证

在临时测试构建中，把 challenge_policy() 替换为文档中的 `return ACTION_FIRE` 原地炮台示例，生产源码仍保留默认挑战逻辑。

训练基准的回归指纹和训练结果保持不变，挑战对手结果单独变化：

| 种子 | 同一训练基准结果 | 原地炮台挑战胜/负/平 |
|---|---|---|
| 750 | 322 / 153 / 25 | 247 / 236 / 17 |
| 1 | 312 / 155 / 33 | 244 / 244 / 12 |
| 42 | 324 / 149 / 27 | 245 / 239 / 16 |

这验证了只改挑战函数不会改变训练基准，也验证了挑战胜率降低不会被测试脚本错误地视为“必须弱化对手才能通过”。示例可在 `-Wall -Wextra -Werror` 下编译。

完整输出：[policy_stationary_example_results.txt](policy_stationary_example_results.txt)。
