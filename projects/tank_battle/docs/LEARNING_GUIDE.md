# 飞行子弹状态下的表格强化学习

## 为什么原来的位置 Q 表不够

坦克位置相同，但一颗子弹正在飞来、已经反弹一次或根本没有子弹时，正确动作可能不同。若只记录双方位置，学习器会把这些情况混在一起。

本 Demo 的完整状态包含：蓝方位置 8 位、红方位置 8 位、红方策略时钟 2 位，以及每方各 23 位的子弹描述（活动 1 位、细分 x/y 各 8 位、方向 4 位、碰撞次数 2 位）。不活动的子弹统一编码为 0。

通过 `Battle_StateKey()` 得到64 位状态键。回合计时上限只是采样截断，不作为环境真正终止，所以 TD 更新在超时时仍 bootstrap。屏幕动画和随机数发生器不是物理状态的一部分。

## 为什么使用稀疏表

完整状态空间非常大，但单次训练只访问其中一部分。固定 262,144 个哈希槽，每项 40 字节，总共 10 MiB，放在板载 16 MiB SDRAM。

查找先计算哈希桶，再比较完整 64 位键，最多探测 16 个槽。如果这段局部范围已满，替换访问次数最低的一项。不同状态不会因为哈希值相同而共享 Q 值，但替换会导致遗忘。

评估只查找已有条目，不插入、不增加访问次数、不改变训练 RNG。对于未学过/全零的状态，用状态键决定固定的平局顺序，不偷偷调用寻路或躲避逻辑。

## 一次交互的顺序

1. 蓝方根据当前完整状态选动作，红方根据同一个旧状态执行固定规则。
2. 同步处理双方移动，冲突则都取消；进入已有子弹格子会受伤。
3. 允许没有在飞子弹的一方发射，方向此时固定。
4. 推进四个半格子步，每个子步先更新双方弹丸，再共同检查命中。
5. 记录胜负/超时，得到奖励，更新实际执行动作的 Q 值。

细分子步的目的不是让子弹“跳两格”，而是让子弹比坦克快，并确保中间格子的墙和坦克不会漏检。

## 反弹计数

弹丸保存 `collisions`。第一次、第二次墙碰反射对应方向分量；第三次把 `active` 置 0。反弹子步先留在墙前，下一子步沿反射方向移动。

碰撞次数与飞行拍数无关：在开阔走廊飞三拍不会自动消失。反弹可能把弹丸送回发射者，因此自己的弹丸也必须出现在学习状态中。

## 奖励与 TD

基础奖励：获胜 +20，失败 -20，同时命中 -4；每拍 -0.02，撞墙/移动冲突额外 -0.15，在已有弹丸时无效开火额外 -0.05。

额外使用势函数 shaping：`Φ(s)=-0.05*双方最短路距离`，附加 `γΦ(s')-Φ(s)`，真正终点的 Φ 为 0。距离表用于固定红方和奖励，不直接告诉蓝方该选择哪个动作。

Q-learning 更新为：

```c
future = terminated ? 0 : max_a Q(next_state, a);
td = reward + gamma * future - Q(state, action);
Q(state, action) += alpha * td;
```

α=0.18，γ=0.96；探索率从 100% 在 45,000 回合内降到 3%，共训练 60,000 回合。演示/评估关闭探索，训练完成后不继续更新模型。

## 如何判断学到了什么

先与随机动作基线比较，再固定 Q 表，用独立出生序列统计胜、负、平和超时。不要只挑几局蓝方获胜的画面来报告效果。

可以依次修改红方反应周期、子弹速度、反弹上限或地图，再重新从零训练，并同时观察胜率、表占用和替换次数。一次只改一项，保留相同随机种子对照。


最终版本使用 16 档方向和 1/16 格位置，不把斜向飞行强行吸附到格子中心。用线段扫掠检查坦克命中，墙面碰撞反射对应速度分量。未反弹的自弹有炮口保护，反弹之后可以伤到发射者。
