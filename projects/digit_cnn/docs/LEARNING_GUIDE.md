# 从 C 数组理解 CNN

## 先读哪几个函数

`DigitCNN_Run()` 按固定顺序调用各层；`conv3_relu()` 是最重要的计算循环。先拿一个输出通道、一个输出像素，跟踪其 `sum`，再查看池化与全连接如何使用结果。

卷积权重布局为 `[输出通道][输入通道][核行][核列]`，特征布局为 `[通道][行][列]`。地址公式为：

```c
input[channel * side * side + y * side + x]
weight[((out_channel * in_channels + in_channel) * 3 + ky) * 3 + kx]
```

3×3 same 卷积在边缘缺少的像素按 0 处理，输出空间尺寸不变。代码中跳过越界项，等价于乘以 0。卷积后 ReLU 把负数置零。2×2 最大池化让每个通道的宽高减半，但不改变通道数。

## 各层尺寸和计算量

| 层 | 输出 CHW | 权重数（不含偏置） | 乘加次数 |
|---|---|---:|---:|
| 卷积 1 | 8×28×28 | 72 | 56,448 |
| 池化 1 | 8×14×14 | 0 | 0（只有比较） |
| 卷积 2 | 16×14×14 | 1,152 | 225,792 |
| 池化 2 | 16×7×7 | 0 | 0 |
| 全连接 | 10 | 7,840 | 7,840 |

合计 9,064 个权重、34 个偏置，9,098 个 float32 参数共 36,392 字节；约 29 万次乘加不包含偏置、激活、池化和 Softmax 的额外开销。

## 为什么只要两个工作区

输入先写 `work_b`，卷积结果写 `work_a`，池化又写回 `work_b`。后一层不会同时读取已经被覆盖的旧数据，所以能够复用缓冲。

`work_a` 最大 6,272 个 float，`work_b` 最大 1,568 个 float，总共 31,360 字节。ARM 上通过 `.cnn_workspace` 段放在 DTCM；每个有效元素都在读前覆盖，因此不要求启动时清零这块 NOLOAD 区。

DMA 采集帧放在 SDRAM，CPU 先复制到自己持有的 AXI SRAM 副本，再送预处理。不要在 DMA 正写的图像上直接做卷积，否则输入可能来自不同帧。

## 预处理为什么比缩成 28×28 更复杂

MNIST 的数字在居中的小内容框内，背景接近 0。镜头看到的纸张可能有阴影、偏移、倾斜和粗细差异，因此需要先找到笔画，再保持比例缩放和对齐。

本实现用 Otsu 阈值找到深色区域，以 8 邻域连通域确定单个数字的包围框；缩放时仍读取原灰度，保留边缘灰度。内容最长边缩至 20 像素，补边到 28×28 后再做灰度重心对齐。

若背景、纸边或多个数字进入框内，最大连通域可能不再是你期望的那个数字。因此先使用清晰、粗笔画、独立的单数字。右下角输入预览比最终类别更能帮助定位问题。

## 建议实验

1. 对比一张测试图在 Python 与 C 中的 logits，确认数组布局和 padding。
2. 修改预处理的内容大小或去掉重心对齐，运行原生合成相机测试，观察变化。
3. 捕获自己的纸面输入，记录正确类别，建立真实光照下的独立测试集。
4. 对比不同置信度/连续帧条件下的误识别与拒识率。
5. 等 FP32 管线稳定后，再学习 INT8 量化与 CMSIS-NN，逐层对照数值和耗时。

不要把 Softmax 的 99% 当作现实中 99% 的正确率。它是在“必须从 10 个数字里选一个”的模型假设下给出的归一化分数。
